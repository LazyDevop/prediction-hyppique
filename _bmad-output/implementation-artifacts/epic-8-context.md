# Epic 8 Context: Comptes, connexion et appareils

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Turn the app into a multi-user service: a user creates an account or signs in with a phone number and a one-time code (no password), protects the app on the phone with a local PIN, recovers the account through a verified backup email when the number changes, sees and removes devices within the tier's device limit, attaches a computer's web app by QR code, and finds followed races, engine settings and retained forecasts on every device. It is the identity and session foundation that Epic 9 (entitlements, payment), Epic 11 (published forecasts per tier) and the Multi retained-forecast sync build on.

## Stories

- Story 8.1: Créer son compte et se connecter par son numéro
- Story 8.2: Session sécurisée et renouvellement des jetons
- Story 8.3: Code PIN et verrouillage
- Story 8.4: Profil et email de secours
- Story 8.5: Récupérer son compte et changer de numéro
- Story 8.6: Mes appareils et limite d'appareils
- Story 8.7: Rattacher son ordinateur par QR code
- Story 8.9: Suivre une course
- Story 8.8: Retrouver ses sélections et pronostics sur tous ses appareils

## Requirements & Constraints

- **OTP login:** code valid 5 min, 5 attempts, requests limited per number (binding) and per IP (generous, CGNAT). Same response body and HTTP code whether the number has an account or not. An account is created only if the request carries acceptance of the terms in their current version (`CGU_VERSION`); errors `code_expire`, `trop_d_essais`, 429 on rate limit.
- **PIN:** 4–6 digits, never sent to the server (test captures all traffic), local gate only; locks on background and after `DELAI_VERROUILLAGE` inactivity; works offline; 5 wrong PINs wipe the local session (cached race data stays). No PIN and no Unlock gate on the web.
- **Session:** 15-min access token; refresh token bound to the device, rotated on every use; reuse of a rotated token revokes the device's whole chain. 401 → app tries one refresh, then opens Connexion.
- **Recovery / number change:** only via verified email; new number verified by OTP, then confirmation link to the email; 24–48 h security delay (`DELAI_CHANGEMENT_NUMERO_HEURES`) with alerts to old number and email, one-tap cancel; rights and data follow the account. New number already owning an account → `numero_deja_utilise`, no merge. No email → no recovery at launch.
- **Devices:** every browser counts; over the tier limit the new device is blocked and nobody is disconnected; new device → SMS alert (never push) and « Nouveau » in Mes appareils.
- **Sync:** last write wins by server receive time, never device time; retained forecast accepted only if received before race start (server UTC), else `recu_apres_depart`; refused local versions are never deleted. Offline stays fully usable; sync only on app open or explicit refresh, no background task. Web has no local cache and no web-only feature.
- **Data minimisation:** no OTP, PIN or token in clear server-side or in audit; secrets only in server environment; fake `otp_client` / `email_client` for tests and dev (code/link readable in dev logs only, never in production).
- **Open values (provisional config until PRD OQ 14/17/19 close):** `DELAI_VERROUILLAGE`, `DELAI_CHANGEMENT_NUMERO_HEURES`, `LIMITE_APPAREILS_<PALIER>`, `WEB_APPAREIL_INACTIF_JOURS`, `JETONS_GESTION_APPAREILS_PAR_JOUR`; OTP provider (also SMS alerts) and email provider unchosen.

## Technical Decisions

- **Ports (hexagonal):** `backend/app/data/otp_client.py` (WhatsApp preferred, else SMS) and `email_client.py` are the only modules knowing their provider; routes in `api/routes_auth.py`.
- **Schema `comptes` (Alembic revisions per story, `timestamptz`):** `compte` (E.164 number unique, random `identifiant_court` never derived from number, `cgu_version_acceptee`, `cgu_acceptee_le`, later `email`, `email_verifie_le`); `code_otp` stores HMAC-SHA256 of the code under `OTP_HMAC_CLE`, constant-time compare; `appareil` (type `telephone`/`navigateur`, readable name, `derniere_activite_le`, `retire_le`); `session` (refresh token hash, `remplace_par`, `revoque_le`, `expire_le`); `lien_verification_email`; sync tables keyed by `cle_course` (never `course_id`).
- **Tokens:** access JWT EdDSA/Ed25519 with `kid`, key distinct from entitlement-proof key, rotation tested, other algs and `none` rejected. Phone: tokens, 128-bit random device id (generated at first launch, new on reinstall) and Argon2id PIN hash in `flutter_secure_storage` (pinned version) — never `shared_preferences` or `hippique_cache.db`; tokens not encrypted by the PIN. Web: refresh in `__Host-` cookie (httpOnly, Secure, SameSite=Strict, Path=/, no Domain) on `app.<domaine>/api` same origin, access token in memory, anti-CSRF header on every state-changing request, no credentialed CORS.
- **Device limit:** limit check + `appareil` insert in one transaction with a row lock on the account (concurrent test). Blocked device gets no `appareil` row/refresh token, only a device-management token: scope `appareils:gerer`, 10 min, bound to account + refused device id, opens only `GET /moi/appareils` and one `DELETE /moi/appareils/{id}`; everything else 403; capped per day (429).
- **QR pairing:** one-time 2-min token stored by hash with requesting browser; phone (type telephone, open session) approves; web polls `GET /appairage/{id}/statut` (public, rate-limited per IP) every 2 s up to 2 min; the poll after approval sets the cookie and returns the access token exactly once. Scanner package (e.g. `mobile_scanner`) pinned at 8.7.
- **`palier_actif(compte)`** single function in `backend/app/api/deps_droits.py`, returns `PALIER_PAR_DEFAUT` (`gratuit` in prod) until story 9.1 replaces it without changing callers.
- **Audit:** device add/remove, email change, number-change request/cancel/apply go to the audit journal (story 7.10).
- **Local cache:** `course_suivie` table (`cle_course`, `suivie`, `modifiee_le`, `synchronise`) then `synchronise`/`motif` columns on retained forecasts, each in a new `hippique_cache.db` version; `onCreate` straight to latest + every `onUpgrade` tested. Purge at 90 days on both copies (app start; daily server command under `role_api`). Expert engine coefficients stored but not returned to tiers that can't use them; Multi rows stop syncing when tier drops, server copies survive.

## UX & Interaction Patterns

**Gates before the navigation stack:** Connexion (first launch, expired or wiped session) and Déverrouillage (return to foreground, inactivity) render before the app's navigation stack.

**Connexion — step 1, numéro:** brand « Analyseur Hippique » (gold, uppercase); lead « Votre numéro de téléphone »; sub « Il sert à créer votre compte ou à vous reconnecter. Pas de mot de passe : vous recevrez un code par SMS. » Label « Numéro de téléphone », country field « 🇨🇲 +237 » + number field (meta « 9 chiffres, sans le 0 initial. »). Terms row (whole row ≥ 48dp, unchecked by default, blocks continuing): « J'accepte les conditions générales d'utilisation et la politique de confidentialité. » (links to current version). CTAs: `cta-primary` « RECEVOIR LE CODE PAR SMS », `cta-ghost` « Recevoir le code par WhatsApp ». Footer: « Outil d'aide à la décision — l'outil ne place aucun pari et aucun modèle ne garantit un gain. » TalkBack reads the number digit by digit.

**Connexion — step 2, code reçu (`otp-field`):** header « ← Code reçu »; lead « Saisissez le code à 6 chiffres »; sub « Si ce numéro peut recevoir un code, il vient d'être envoyé au +237 … » + « Modifier le numéro » (neutral wording preserves the no-enumeration rule). One field of 6 boxes, SMS auto-fill (SMS Retriever / User Consent), paste accepted; hint « 📩 Le code se remplit tout seul à la réception du SMS, si votre téléphone le permet. Sinon, tapez-le. »; meta « Code valable 5 minutes · 5 essais au maximum. »; banner « ℹ️ Pas reçu ? Vérifiez le numéro et votre réseau. Le renvoi est possible dans quelques secondes. » Actions: « Valider · 4 chiffres sur 6 » (disabled until complete), « Renvoyer le code · dans 42 s » (disabled, remaining time as text), link « Recevoir le code par WhatsApp ». Error states verbatim: « Code expiré — demandez un nouveau code », « Trop d'essais — demandez un nouveau code », « Trop de demandes — réessayez dans quelques minutes ». TalkBack: single node « Code reçu par SMS, 6 chiffres », each digit announced, « Code rempli automatiquement » on auto-fill; no short timeout interrupts entry.

**Connexion — step 3, choix du PIN (`pin-pad`):** header « Code PIN »; lead « Choisissez un code PIN »; sub « 4 à 6 chiffres. Il déverrouille l'app sur ce téléphone. Il reste sur ce téléphone et n'est jamais envoyé. »; progress text « 3 chiffres saisis · encore 1 au minimum »; « Continuer » then confirmation step (« Vous le confirmerez à l'étape suivante. »).

**Déverrouillage:** brand centered; « Saisissez votre code PIN »; « Compte +237 6 •• •• •• 56 »; dots with text « 2 chiffres saisis sur 4 »; auto-validate at chosen length. Wrong PIN: « Code incorrect — N essais restants » in a polite live region (mockup shows strong banner « Code PIN incorrect. 3 essais restants. Après 5 essais, il faudra vous reconnecter par code SMS. »); 5th: « Session effacée — reconnectez-vous par code SMS » → Connexion. Link « Code oublié ? Se reconnecter par code SMS ». Works offline.

**`pin-pad` rules:** 3×4 grid, ten digits + « ⌫ Effacer », keys ≥ 48dp (mockup 64), never the system keyboard, dots without digits. TalkBack: each key labelled by its digit, entry zone one node announcing « 3 chiffres sur 4 saisis » without the digits; error never by vibration or colour alone.

**Tokens used:** `bg #0B1120`, `surface #131C2E`, `surface-2 #0F1728`, `line-card rgba(255,255,255,.36)` (all field/key/card borders), `line rgba(255,255,255,.08)` (terms row separators), `text #E7E4DA`, `muted #8B93A7`, `gold #E8B33C` + `on-gold #14100A` only for `cta-primary` (« Recevoir le code ») and brand/title and `focus-indicator` (2px gold outline, 2px offset). `pin-pad`: keys `surface`, `line-card` border, `rounded.md` 10px, digits `headlineSmall` tabular in `text`; dots filled `text`, empty `line-card` outline; error text in `text`, never red. `otp-field`: `surface`, `line-card`, `rounded.sm` 8px, min height 48dp, digits `headlineSmall` tabular, hint `muted`; active box shown by `focus-indicator`, not another colour. `cta-primary`: gold fill, uppercase, `rounded.md`, one per screen; `cta-ghost`: `surface` + `line-card` + `text`. `status-banner`: `surface`, `line-card`, `rounded.sm`; strong variant 2px `text` border. Labels ≥ 11sp; all digits tabular; no shadows, no red/green for system states.

**Other surfaces:** Profil (account icon on Accueil): number, backup email « vérifié »/« non vérifié », tier and end date, accepted terms version/date, entries « Mes appareils », « Scanner un QR code », offers only once their stories ship (absent, never disabled); paid tier without verified email → non-blocking « Ajoutez un email de secours pour pouvoir récupérer votre compte ». Mes appareils: `device-row` (« Téléphone Android », « Chrome sur Windows », last activity, « Cet appareil », « Nouveau », `cta-ghost` « Retirer » with light confirmation; grouped TalkBack node). Appareil bloqué: « Votre palier permet 2 appareils, déjà utilisés », « Aucun appareil n'a été déconnecté. », « Retirer un appareil », « Découvrir l'offre Duo » (text only, « Souscrivez depuis un appareil déjà connecté »). Restricted mode: « Retirez un appareil pour connecter celui-ci », « Accès limité : un seul retrait, pendant 10 minutes. », confirm « Retirer Chrome sur Windows ? Il sera déconnecté et une alerte partira vers votre numéro. », then « … a été retiré. Reconnectez-vous pour utiliser cet appareil. » + « SE RECONNECTER »; timeouts « Délai dépassé — reconnectez-vous pour réessayer », « Trop de tentatives aujourd'hui — réessayez demain, ou retirez un appareil depuis un appareil connecté ». Pairing: web `qr-pairing` with remaining time as text and « Se connecter par code SMS »; phone sheet « Connecter Chrome sur Windows à votre compte ? » (« Approuver » / « Refuser »); expired « QR code expiré — affichez-en un nouveau sur l'ordinateur »; web flow fully keyboard-operable. `followed-race`: star toggle + « Suivre » / « Suivie », ≥ 48dp, no confirmation, offline on Android; « Courses suivies » section at top of Accueil hidden when empty. Recovery from Connexion via « J'ai changé de numéro ».

## Cross-Story Dependencies

- 8.1 needs Epic 7 stories 7.2 (PostgreSQL schemas/roles), 7.4 (rate limits), 7.9 (`CGU_VERSION`), 7.10 (audit writer). Order: 8.1 → 8.2 → 8.3 → 8.4 → 8.5 → 8.6 → 8.7 → 8.9 → 8.8.
- 8.2's session opening completes 8.1's verify route; 8.3 PIN step follows the first successful session; 8.5 requires 8.4's verified email; 8.6 limit check also governs 8.7's paired browser.
- 8.8 depends on 8.9 (local followed races) and story 5.20 (device-side sending of retained forecasts; if absent, ship server side only).
- Epic 9: 9.1 replaces `palier_actif`; 9.3 entitlement proof uses the device id from 8.2 with a separate key; 9.11 adds SIM-swap cooldown on paid accounts; « Découvrir l'offre Duo » and Profil offers appear once Offres (Epic 9) exists. Epic 11.2 needs 8.1 and 8.2.
